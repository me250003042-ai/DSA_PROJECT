# D3: Two-Heap Method for Finding a Fixed Percentile

## 1. Objective

We want to maintain the p-th percentile of a changing set of elements using two heaps.

The data can change through:
- Insertion of new elements.
- Retraction or deletion of existing elements.

Our goal is to find the required percentile efficiently after every update.

We use two heaps:
- A Max-Heap called L.
- A Min-Heap called R.

## 2. Basic Idea

The two heaps divide all active elements into two parts.

**Max-Heap L:**
- Stores the smaller elements.
- Its root contains the largest element in L.

**Min-Heap R:**
- Stores the remaining larger elements.
- Its root contains the smallest element in R.

Let:
- n = total number of active elements.
- p = required percentile, where 0 < p <= 1.
- k = ceil(p * n).

We maintain the following size condition:

    size(L) = ceil(p * n)

The remaining elements are stored in R.

Therefore:

    size(R) = n - size(L)

## 3. Invariants

The algorithm maintains three important properties.

**Invariant 1: Size Property**

The number of elements in L must always be:

    size(L) = ceil(p * n)

**Invariant 2: Ordering Property**

Every element in L must be less than or equal to every element in R.

In other words:

    maximum(L) <= minimum(R)

**Invariant 3: Membership Property**

L contains the k smallest active elements, while R contains all the remaining elements.

These properties ensure that the required percentile is always available at the root of L.

## 4. Finding the Percentile

Since L contains the k smallest elements, its largest element is the k-th smallest element in the complete data set.

Therefore:

    p-th percentile = maximum(L)

Since L is a Max-Heap, its maximum element is available at its root.

Hence, finding the percentile takes O(1) time.

## 5. Insertion Operation

When a new element x arrives:

1. If L is empty or x is less than or equal to the root of L, insert x into L.
2. Otherwise, insert x into R.
3. Calculate the new required size of L using ceil(p * n).
4. Rebalance the heaps until the size and ordering properties are satisfied.

During rebalancing:

- If L contains too many elements, move its root to R.
- If L contains too few elements, move the root of R to L.

Each heap insertion or removal takes O(log n) time.

Therefore, insertion takes O(log n) time.

## 6. Retraction Operation

When an existing element is retracted:

1. Mark that element as deleted.
2. Update the corresponding live element count.
3. Calculate the new required size of L.
4. Rebalance the heaps if necessary.
5. Remove deleted elements from heap roots whenever they reach the top.

Lazy deletion can be used so that elements do not need to be searched for and physically removed from the middle of a heap.

Periodic rebuilding can remove accumulated deleted elements.

With this approach, the update cost is O(log n) amortized, assuming the rebuilding policy keeps the number of stored heap entries proportional to the number of active elements.

## 7. Correctness Proof

We prove that the algorithm always returns the correct p-th percentile.

Initially, both heaps are empty, so the properties hold.

Assume that before an update:

- L contains the k smallest active elements.
- R contains all remaining active elements.
- Every element in L is less than or equal to every element in R.

After an insertion or retraction, the total number of active elements may change.

The algorithm updates the required size of L to ceil(p * n) and rebalances the heaps.

During rebalancing, elements are moved between heaps using their roots.

Because the ordering property is maintained, moving the largest element of L to R or the smallest element of R to L preserves the sorted division of elements.

Thus, after rebalancing:

- L again contains the k smallest active elements.
- R contains all remaining active elements.
- The size and ordering properties are restored.

Therefore, by induction, the three invariants remain true after every update.

Since L contains the k smallest elements, its maximum element is the k-th smallest element.

Hence, the root of L always gives the required p-th percentile.

The algorithm is correct.

## 8. Time and Space Complexity

| Operation | Time Complexity |
|---|---|
| Insert an element | O(log n) |
| Retract an element | O(log n) amortized |
| Rebalance heaps | O(log n) per moved element |
| Find percentile | O(1) |
| Space complexity | O(n) |

Periodic rebuilding takes O(n) time when performed, but with a suitable purge threshold its cost can be amortized across updates.

## 9. Conclusion

The two-heap method efficiently maintains a fixed percentile in a changing data set.

The Max-Heap stores the required smallest portion of the elements, and the Min-Heap stores the remaining larger portion.

By maintaining the size and ordering properties, the required percentile is always available at the root of the Max-Heap.

Thus, the method supports:
- Insertion in O(log n) time.
- Retraction in O(log n) amortized time.
- Percentile queries in O(1) time.

This makes the two-heap approach useful for maintaining running percentiles in streaming applications.
